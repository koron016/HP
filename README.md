# WSTI — Work Style Type Indicator（働き方16タイプ診断）

**20の質問**で、仕事の進め方が **16タイプ**のどれかに分かれる診断サイトです。
MBTIと同じ4文字のタイプ名（例：`DTEC`）に加えて、**強み・気をつけたいこと・力が出る環境・
自己PRのたたき台**まで出ます。就活や転職でそのまま使えることを狙っています。

**英語と日本語の2言語**に対応しています。ブラウザの言語設定で自動的に切り替わります。

HTML・CSS・JavaScript だけで動くので、**サーバー代も維持費もかかりません**。

---

## 4つの軸

| 軸 | 片方 | もう片方 |
|---|---|---|
| 決め方 Deciding | **I** 直感 Instinct | **D** 根拠 Data |
| 進め方 Working | **S** 単独 Solo | **T** 巻き込み Together |
| 締切 Timing | **E** 前倒し Early | **L** 追い込み Late |
| 立ち位置 Standing | **C** 仕切る Command | **B** 支える Backbone |

2×2×2×2 = **16タイプ**になります。

## 中身を書き換える

`assets/quiz-data.js` を開いてください。**すべての文章が `{ ja: "...", en: "..." }` の形**で並んでいます。

### 守るべき決まりが3つ

**1. 書き換えたら、必ずこれを実行する**

```bash
node tools/build.js
```

結果ページとシェア画像が作り直されます。忘れると、サイトの表示とXでシェアされた内容がズレます。

> シェア画像も作り直す場合は `npm install playwright` が必要です。
> 無い場合は画像を飛ばして、結果ページだけ作り直します。

**2. 日本語と英語を両方書く**

片方だけ書くと `node tools/build.js` がエラーで止まります。英語だけの文章が日本語版に
混ざって出てしまうのを防ぐためです。

**3. 点数は奇数だけ、1軸に奇数個の質問**

点数は ±1・±3 だけを使い、1つの軸には5問（奇数個）置いています。
**奇数を奇数個足すと必ず奇数になる**ので、合計が0（引き分け）になりません。
0になるとタイプが決まらないためです。崩すと `node tools/build.js` がエラーで止まります。

## 毎朝の投稿文を自動で用意する（無料）

**毎朝7時に、その日のX投稿文がGitHubのIssueとして立ちます。**
スマホのGitHubアプリに通知が来るので、**枠の中をコピーしてXに貼るだけ**です。

```
毎朝7時 → GitHub Actions が動く → 投稿文をIssueにする → 通知 → コピーして貼る
```

### Xの自動投稿にしていない理由

X APIは2026年2月6日に無料枠が廃止され、**新規は従量課金だけ**になりました
（1投稿 $0.015、リンク付きは $0.20）。この仕組みは**X APIを一切使いません**。
GitHub Actions は公開リポジトリなら無料なので、**合計0円**です。

貼る手間は10秒ですが、**大変なのは「今日何を書くか」を決めるほう**です。そこを自動化しています。

### 準備（1回だけ）

**リポジトリの Settings → General → Default branch を
`claude/claude-md-docs-3bgn2h` に切り替えてください。**
GitHub Actions の定時実行は、**デフォルトブランチにあるワークフローしか動きません**。
切り替えないと毎朝の起動だけが動きません（手動実行はできます）。

> 60日間リポジトリに変更がないと、GitHubが定時実行を止めます。
> 止まったら Actions のページで「Enable workflow」を押せば戻ります。

### ネタの中身

投稿文は **`assets/quiz-data.js` から自動で組み立てています**。手で書いた文章はありません。
6種類 × 全項目で**56日分**あり、一周したら最初に戻ります。

| 種類 | 中身 | 出どころ |
|---|---|---|
| 今日の16タイプ | タイプ名・キャッチ・強み・ただし書き | `types` |
| 説明会で聞くといい質問 | 逆質問と、返答の○△×の読み方 | `env[*].ask` / `read` |
| 深掘り3段階 | 面接官が掘る3つと、崩れない答え方 | `chain` |
| 短所の答え方 | 聞かれ方・答え方・備え方 | `prep` |
| 合わないサイン | 警戒したい言葉と、確かめる質問 | `env[*].flag` |
| チームの偏り | 起きることと打ち手 | `risks` |

**投稿文を増やしたいときは `quiz-data.js` を足してください。**
`daily-post.js` に文章を書き足す作りにはしていません。

### 手元で確認する

```bash
node tools/daily-post.js          # 今日の分
node tools/daily-post.js --all    # 56日分ぜんぶ
node tools/daily-post.js --day 12 # 13日目の分
```

文字数はXの数え方（全角2文字・URLは23文字）で数えていて、**280を超えたら
後ろの行から自動で落とします**。はみ出した文章がそのまま出ることはありません。

Issueを立てる場所は、いま**すぐ手で試せます**。
Actions → 「今日のX投稿文をIssueにする」 → **Run workflow**。

## チーム分布ページ（`team.html`）

メンバーのタイプを選ぶと、**チームの偏り**と**足りていない持ち味**が出ます。
選んだ内容はURLに入るので、リンクを送るだけで共有できます。サーバーは要りません。

### これは選考に使えません

**重要な制約です。** この診断は選択肢の良し悪しが見えるため、答えを取り繕えます。
本物の適性検査にある「ライスケール」（同じ趣旨の質問を言い換えて矛盾を検出する仕組み）も
入っていません。MBTIの発行元自身も、採用選考への使用を非倫理的として禁止しています。

**合否の判断には使わないでください。** 想定している用途は、入社後の相互理解、配属、
チーム編成、そして採用広報です。ページにもその注意書きを常時表示しています。

## 就活生にとっての「使う理由」

診断で終わらせず、**そのまま就活で使える 材料を出します**。

| 出るもの | 使う場面 |
|---|---|
| 自己PRのたたき台（一文） | ES・面接 |
| 強み3つ・気をつけたいこと2つ | 自己分析・短所の質問 |
| **合う環境の条件 4つ** | 求人票を読むとき |
| **説明会・面接で聞くこと 4つ** | **そのまま逆質問に使えます** |
| **合わないサイン 4つ** | 説明会で警戒すべき発言 |

**実在の企業名は出しません。** 個人サイトが「この会社が向いています」と言っても信用されませんし、
データはすぐ古くなります。代わりに**本人が自分で見極めるための道具**を渡す形にしています。
文言は `quiz-data.js` の `env` にあり、4つの軸それぞれの側ごとに用意しています。

### 他の就活サイトに無い2つ

質問リストはどこにでもあります。**その先の2つ**がこのサイトの理由です。

**1. 深掘りの3段階（`chain`）**

面接官は同じ話を3回掘ります。学生は1段目しか用意しないので、**2段目・3段目で崩れます**。
3段全部と、崩れないための言い換えを出します。

> 1 チームで動いた経験を教えてください
> 2 その中で、あなたの役割は何でしたか？
> 3 なぜ、あなたがその役割になったのですか？ ← ここで崩れる
> **崩れない答え方** 「与えられました」ではなく「自分で取りに行きました」の形にする

**2. 逆質問の答えの読み方（`env[*].read`）**

質問を渡すだけでは足りません。**返ってきた答えをどう解釈するか**まで出します。

> 「入社して何年目から、自分で決められるようになりますか？」
> ○「1年目から自分の判断で動いてもらいます」
> △「人によります」→ 実例を1つ聞く。答えられなければ実績がない
> ×「まずは3年、しっかり学んでもらいます」→ 決める機会は当分ない

**△の枝がいちばん重要**です。はぐらかされたときに、もう一段聞けるようにするためです。

### MBTIとの違いは「処方箋」

軸が4本で16タイプ、という構造だけならMBTIと同じです。**違うのは、偏ったチームに対して
「何が起きるか」と「どうするか」を出すこと**です。

例：根拠型に75%以上偏ったチーム
> **この偏りで起きること** — 材料が揃うまで決まらず、判断が遅れて機会を逃す
> **打ち手** — 「この日までに決める」と、情報が揃う前に期限を切っておく

MBTIは個人を見る道具なので、**組み合わせが生む事故については構造上なにも言えません**。
ここが企業にとっての実利になります。文言は `quiz-data.js` の `risks` にあります。

### キャラは描かず、コードから導出しています

`assets/character.js` が4文字のコードから見た目を組み立てます。
1文字目が頭の形、2文字目が目、3文字目が体の傾き、4文字目が腕です。
絵を1枚ずつ用意していないので、**16体すべてが必ず違い、タイプを増やしても描き足す必要がありません**。

### 拡散の観点でここが効く

企業が「うちのチームはこういう分布でした」と**自分から公開したくなる**形にしてあります。
採用広報になるからです。企業が発信してくれれば、それがそのまま拡散になります。
候補者側も分布を見て自分に合うか判断できるので、**企業側の理解と話題性が同じ方向を向きます**。

## なぜこの作りなのか（調査にもとづく設計）

- **4文字のラベルが商品本体です。** 16Personalitiesは月約1,930万アクセスで、うち38%が直接アクセス。
  韓国ではMBTIがInstagramのプロフィール欄やマッチングアプリの項目になっています。
  **ラベルはサイトの外で生きる**ので、名乗れる形にすることが最優先です
- **正確さでは勝負しません。** MBTIは5週間以内の再受験で39〜76%が別タイプになります。
  科学的に妥当なBig Fiveは連続値なのでラベルにならず、広まりません。
  **正確さとシェアされやすさは両立しない**ので、後者を取っています
- **最初から2言語です。** 日本語だけでは世界で話題になりようがありません
- **名前をMBTI型にしています。** 2026年4月にSBTIが同じ型でTikTokとWeiboで数百万人に届いています
- **質問数は20問です。** 世界で通用しているものは長く、16Personalitiesは約60問、
  TikTokでバズったSBTIは32問。8問では結果が当てずっぽうに見えます
- **結果に持ち帰れる中身を入れています。** 16Personalitiesが就活で使われているのは、
  強みと弱みが詳しく書かれていて、そのままESや面接に使えるからです
- **タイプごとの静的ページ**があるので、シェアされるとそのタイプの画像が出ます
- **相性は計算で出しています。** 手書きすると必ず食い違うので、コードから導出しています

## 動作について

- スマートフォン優先。結果画面はスクリーンショットで映える作りにしています
- キーボードの `1`〜`4` でも回答できます
- 言語は `?lang=en` / `?lang=ja` でも指定できます
- JavaScriptが無効だと使えません（その旨のメッセージが出ます）
